# Repository Guidelines

## Session Start

At the start of every Codex session, inspect `git status --short --branch` and the current branch before editing. Check Git and GitHub for the current commit and pull request state instead of relying on a manually maintained status file. Keep existing project conventions and deeper `AGENTS.md` rules. Keep this file suitable for a public repository: no credentials, private notes, personal paths, or confidential infrastructure details.

## Project Structure & Architecture

CCTV Viewer is a German recording viewer with a Go backend and a TypeScript frontend. The entry point is `cmd/cctv/`; server logic and Go tests live in `internal/viewer/`. Frontend source is in `web/src/`. `web/dist/index.html`, `style.css`, and `theme.js` are maintained sources; `web/dist/app.js` is generated by the build. Playwright tests live in `tests/`, and release/workflow tests in `scripts/test_*.py`. Preserve the existing architecture and keep original recordings read-only.

## Build, Test & Development Commands

- `npm ci`: install the locked frontend dependencies.
- `npm run typecheck`, `npm test`, `npm run build`: check TypeScript, run unit tests, and rebuild `web/dist/app.js`.
- `go vet ./...` and `go test -race ./...`: inspect and test the backend.
- `go build -o bin/cctv ./cmd/cctv`: build the local server.
- `npm run test:browser`: run Playwright after the frontend and Go builds; its configuration starts the test server. FFmpeg and the matching browser must be available.

For CI/CD changes, also run `python3 -m unittest discover -s scripts -p 'test_*.py'`, `python3 -m compileall -q scripts`, `bash -n scripts/promote_image.sh scripts/smoke.sh`, `actionlint`, and `shellcheck scripts/promote_image.sh scripts/smoke.sh`.

## Coding Style & Tests

Use `gofmt` for Go and the existing TypeScript style; do not add a UI framework. Keep TypeScript modules and functions descriptive, and place unit tests beside their sources as `*.test.ts` or `*_test.go`. Browser tests use `*.spec.ts`; workflow tests use `test_*.py`. For UI changes, check responsive layouts, light/dark themes, focus states, and stored-preference migration. Do not change public APIs, permissions, or database schemas without a matching request.

## Commits & Pull Requests

Start each feature on a dedicated branch, normally `codex/<topic>`. Use Conventional Commits such as `feat: ...` or `fix: ...`. Commit only related files. Submit changes through a PR against `main` with a concise description, test results, limitations, and UI screenshots when relevant. The owner merges manually; agents must not merge, enable auto-merge, deploy, or start an official release. Before every commit and push, inspect the staged diff for secrets, private infrastructure, and local artifacts. Do not rewrite history or discard existing work.

Respect an existing feature branch and uncommitted work. Stage named files, review `git diff --cached`, and run relevant tests before any push. Never push without the user's explicit instruction. Do not bypass a failing secret check with `--no-verify`, alternate hooks paths, or a disabled scanner; investigate and fix the finding. Do not rewrite published history without explicit approval.

## Windows and CachyOS Development

Use repo-relative paths and UTF-8 text with LF for shell scripts. Keep commands usable from PowerShell or a POSIX shell and avoid hard-coded machine paths. Install locked Node dependencies with `npm ci`; use the Go and Node versions required by the project and CI. Keep generated output out of commits unless the repository explicitly tracks it. The shared secret check uses Node and Git on both systems; see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for hook setup.

## Security, Artifacts & Releases

Keep `.env` credentials out of output and commits; `.env.example` must contain placeholders only. Store local reports and screenshots under `.local-reports/` or outside the repository. Do not commit root-level `TEST_REPORT.md` or `UI_REVIEW.md`; update `FEATURE_MATRIX.md` for public feature documentation. If a local artifact was tracked, remove it from Git while preserving the local file.

Read [docs/CI-CD.md](docs/CI-CD.md) and the affected workflows/scripts before changing CI or releases. Preserve the required **Anwendung prüfen** check, PR read-only GHCR access, pinned Actions, and manual `workflow_dispatch` release flow. Main CI publishes commit images only; official version tags and `latest` are not agent test targets. `package.json` is the version source; synchronize both lockfile project versions and fixed UI version strings for requested version changes. Report local tests separately from GitHub and Docker verification.
